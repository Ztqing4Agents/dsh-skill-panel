# v1.1.4

> 类型：规范
> 读者：升级到本版本的人——判断自己会不会受影响、要做什么
> 真源：`CHANGELOG.md` 的 [1.1.4] 节 + git tag `v1.1.4`
> 更新触发：本版本发布后即冻结；只在发现事实性错误时追加「勘误」，不改已发布内容
> 规模上限：400

## 定位

把宿主支持面抬到 DSH `0.2.3` 代际，并把十六条接口的访问策略逐条写成显式的匿名访问；本地数据、界面与交互都不变。

## 亮点

- 宿主声明统一：`engines.dsh` 与七条 `@deepseek-ai/dsh-*` peer 一致为 `>=0.2.3-0 <0.3.0-0`（`-0` 是让预发布宿主落进比较子的写法）。
- npm 消费者工程与 `0.2.3` 系列宿主一起安装时不再报 `ERESOLVE`。
- 十六条接口逐条显式声明匿名访问：宿主自 `0.2.3` 起把缺省值当「必须已登录」，不写就会让没有凭据的调用被挡下。

## 新装

```bash
dsh plugin --profile <your-profile-name> add @ztqing4agents/dsh-skill-panel
```

装完重启 DSH，侧栏出现「技能」入口；桌面端可在「插件」页点「添加插件」填上面的包名。

## 升级与迁移

- **【不兼容】支持面换代际**：DSH `0.2.2` 系列（含 `0.2.2-rc.*`）不再受支持。仍在这一代宿主上的用户请**安装 `1.1.3`**——已装版本可继续正常使用，但不再接收后续修复；待宿主升级到 `0.2.3` 及以上，再升级本插件。
- 在 `0.2.3` 及以上的宿主上升级不需要额外动作：数据目录、安装台账与开关状态都不动，重启 DSH 即可生效。
- 宿主拒绝安装时给出的精确版本豁免入口是逃生门而非支持面——长期停在 `0.2.2` 上不会收到本版之后的任何修复。

## 已知问题

- 仍停在 `0.2.2` 系列的用户收不到本版及之后的修复，只能停在 `1.1.3`。
- 本版的真机验证只在 `0.2.3-alpha.2` 上做过；`0.2.3` 后续预发布版或正式版若改变宿主接口形状，需要先在本插件侧适配再升级。

## 验收

- `npm view @ztqing4agents/dsh-skill-panel@1.1.4 version` 输出 `1.1.4`。
- `npm view @ztqing4agents/dsh-skill-panel@1.1.4 peerDependencies` 与 `npm view @ztqing4agents/dsh-skill-panel@1.1.4 engines` 里都是 `>=0.2.3-0 <0.3.0-0`。
- 在 `0.2.3-alpha.2` 宿主上装一次并重启：「插件」页有条目、面板能打开，「已安装」与「技能市场」两个页签都正常。
- 在 `0.2.2` 宿主上安装会被拒：npm 侧报 `ERESOLVE`，宿主侧由 `engines` 拒绝并给出精确版本豁免提示。

全量变更见 `CHANGELOG.md` 的 [1.1.4] 节。
