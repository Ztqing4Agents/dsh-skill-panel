# v1.1.3

> 类型：规范
> 读者：升级到本版本的人——判断自己会不会受影响、要做什么
> 真源：`CHANGELOG.md` 的 [1.1.3] 节 + git tag `v1.1.3`

> 规模上限：400

## 定位

技能市场的描述与署名、详情页的概览改按上游站点的取值顺序读取——此前不显示描述、署名显示账号 ID、概览显示英文原文的三类技能升级后与站点对齐；安装行为与本地数据都不变。

## 亮点

- 卡片恢复描述行：此前只剩标题与统计的市场卡片（如 `ppt-generator-skill`）重新显示描述。
- 署名改显示作者名：少数此前显示 `user_` 开头内部账号 ID 的技能，卡片与详情页改为显示作者名，与站点一致。
- 概览显示中文译本：上游提供官方中文译本的技能，详情页不再显示作者英文原文；译本缺失时回落原文。

## 新装

```bash
dsh plugin --profile <your-profile-name> add @ztqing4agents/dsh-skill-panel
```

装完重启 DSH，侧栏出现「技能」入口；桌面端可在「插件」页点「添加插件」填上面的包名。

## 升级与迁移

- **宿主下限**（自 `1.1.2` 起生效）：本插件要求 DSH `0.2.2` 及以上，仍停在 `0.2.0` / `0.2.1` 的会在安装时被拒——npm 侧报 `ERESOLVE`、宿主侧由 `engines` 拒绝，这类用户能用的最新版本仍是 `1.1.1`。
- 在受支持的宿主上无破坏性变更，也没有需要手动执行的迁移：升级后重启 DSH 即可，已装技能、安装台账与开关状态都不动。
- 市场页的描述与署名是读上游的结果，升级并重启 DSH 后重新打开「技能市场」即可看到；已装技能的本地文件不因此改写。
- 一部分技能的描述文案会变：中文描述与作者原文措辞不同的技能（普查 400 行里过半），升级后显示的是平台中文那一段；个别技能的平台中文槽位本身就是英文（如 `han-deck-context`），这类技能反而显示英文，与站点一致。
- 安装仍只写作者原文：中文译本只用来看概览，`skills/<name>` 里不会出现译文。

## 已知问题

- 描述只有一段：同一技能在中文与英文界面下显示的是同一段描述，英文界面读到的也是这段中文文案。
- 同一技能的卡片与详情页署名可能不同（如 `fpt-cli` 卡片是 `loonghao`、详情页是 `Hal`）——上游两条路径各取一槽，与站点一致，不是缺陷。
- 详情页概览显示技能正文全文：站点为少数技能另备短稿，本插件尚未取用，个别技能的概览读起来比站点长。
- 已安装页的描述读本地 `SKILL.md` 的原文，上游改摘要后需重装才同步。

## 验收

- `npm view @ztqing4agents/dsh-skill-panel@1.1.3 version` 输出 `1.1.3`。
- 在「技能市场」搜 `ppt-generator-skill`：卡片带描述行，文字与 skillhub.cn 同名技能页一致。
- 搜 `fpt-cli`：卡片署名显示 `loonghao`，不再出现 `user_` 开头的账号 ID。
- 打开 `fpt-cli` 详情页：概览是中文译文，而技能目录里的 `SKILL.md` 仍是作者原文。

全量变更见 `CHANGELOG.md` 的 [1.1.3] 节。
