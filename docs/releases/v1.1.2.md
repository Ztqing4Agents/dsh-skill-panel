## 定位

把宿主支持面收敛到 DSH `0.2.2` 代际、修好 npm 侧预发布宿主的依赖解析，并把内置插件位的默认图标对齐宿主；本地数据与既有交互都不变。

## 亮点

- 宿主声明统一：`engines.dsh` 与七条 `@deepseek-ai/dsh-*` peer 一致为 `>=0.2.2-0 <0.3.0-0`（`-0` 是让预发布宿主落进比较子的写法）。
- npm 消费者工程与 `0.2.2-rc.x` 宿主一起安装时不再报 `ERESOLVE`。
- 内置插件位在缺图标或图标加载失败时改画宿主同款默认图形，已安装列表块与详情页头统一为框内 `36×36`。

## 新装

```bash
dsh plugin --profile <your-profile-name> add @ztqing4agents/dsh-skill-panel
```

装完重启 DSH，侧栏出现「技能」入口；桌面端可在「插件」页点「添加插件」填上面的包名。

## 升级与迁移

- **【不兼容】支持面收窄**：DSH `0.2.0` / `0.2.1` 系列不再受支持。仍在这两代宿主上的用户请**留在 `1.1.1`**——已装版本可继续正常使用，但不再接收后续修复；待宿主升到 `0.2.2` 及以上，再升级本插件。
- 在 `0.2.2` 及以上的宿主上升级不需要额外动作：数据目录、安装台账与开关状态都不动，重启 DSH 即可生效。
- 宿主拒绝安装时会给出精确版本的豁免入口，那是逃生门而非支持面——长期跑在 `0.2.0` / `0.2.1` 上不会收到本版之后的任何修复。

## 已知问题

- registry 元数据不可改：`npm view @ztqing4agents/dsh-skill-panel@1.1.1 peerDependencies` 仍是旧区间，npm 侧直接装 `1.1.1` 仍会 `ERESOLVE`（`dsh plugin add` 走 pnpm，不受影响）。
- 旧宿主用户（`0.2.0` / `0.2.1`）收不到本版及之后的修复，只能停在 `1.1.1`。
- 内置插件位的默认图形只覆盖「没有图标」与「图标解码失败」两种情况；自带图标的插件仍显示自己的图标。

## 验收

- `npm view @ztqing4agents/dsh-skill-panel@1.1.2 version` 输出 `1.1.2`。
- `npm view @ztqing4agents/dsh-skill-panel@1.1.2 peerDependencies` 与 `npm view @ztqing4agents/dsh-skill-panel@1.1.2 engines` 里都是 `>=0.2.2-0 <0.3.0-0`。
- 在 `0.2.2-rc.5` 宿主上装一次并重启：「插件」页有条目、面板能打开，「已安装」与「技能市场」两个页签都正常。
- 在 `0.2.1` 宿主上安装会被拒：npm 侧报 `ERESOLVE`，宿主侧由 `engines` 拒绝并给出精确版本豁免提示。
- 无图标的内置插件在列表块与详情页头显示宿主默认图形，框内 `36×36`，深色主题下不露色环。
