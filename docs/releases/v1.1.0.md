## 定位

把 npm 包名迁到公共作用域 `@ztqing4agents/dsh-skill-panel`，安装面与插件内部标识解耦。

## 亮点

- 以公共作用域包 `@ztqing4agents/dsh-skill-panel` 发布，插件用法与界面不变。
- 全部 `/api/dsh-skill-panel/*` 接口路由、面板命名空间、样式挂载钩子与本地数据目录保持不变，升级不搬家。
- `client.js` 的装载标识同步为新包名，替掉宿主上因标识不匹配触发的 `loaded without registering` 启动异常。

## 新装

```bash
dsh plugin --profile <your-profile-name> add @ztqing4agents/dsh-skill-panel
```

装完重启 DSH，侧栏出现「技能」入口；桌面端可在「插件」页点「添加插件」填上面的包名。

## 升级与迁移

- **【不兼容】包名变了**：先卸旧包、再装新包，两者**不能同时启用**——同时启用会因注册相同路由报 `webserver: duplicate exact route`：

  ```bash
  dsh plugin --profile <your-profile-name> remove dsh-skill-panel
  dsh plugin --profile <your-profile-name> add @ztqing4agents/dsh-skill-panel
  ```

- 数据目录**不迁移**：不要移动或重命名 `$DSH_HOME/dsh-skill-panel/`，原有收藏、安装台账与内置技能开关状态会自动沿用。
- 升级后重启 DSH 一次即可生效，旧包目录可以删掉。

## 已知问题

- npm 上仍有一个无作用域的同名包 `dsh-skill-panel`，那是第三方无关包，不要装错。
- 更新仍是覆盖升级，没有版本回退入口；回退需要手动移除目录后重装。

## 验收

- `npm view @ztqing4agents/dsh-skill-panel@1.1.0 version` 输出 `1.1.0`。
- 按上文卸旧装新并重启后，DSH「插件」页能看到该插件条目，且没有 `loaded without registering` 之类的启动异常。
- 打开面板，「已安装」页签仍能看到升级前就有的技能与开关状态，说明台账与数据目录沿用成功。
- 走一次市场安装（任选一个技能），装完在「已安装」里能看到它——证明 scoped 包名下安装链路正常。

本页只回答「对升级者意味着什么」，变更条目正文见 `CHANGELOG.md` 的 [1.1.0] 节。
